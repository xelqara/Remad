# Remad Roadmap

## Phase 0 — Foundation

Define the company narrative, ownership policy, contribution controls, dependency register, and brand system. This phase is represented by the current repository.

## Phase 1 — Evidence

Choose one narrow problem, collect lawful and documented data, define evaluation criteria, and publish a reproducible technical note. No market-leadership claims should be made before evidence exists.

## Phase 2 — Prototype

Build a small, measurable prototype with clear input boundaries, output definitions, security controls, and user feedback. Record all components and licenses.

## Phase 3 — Pilot

Run a limited pilot with explicit users or partners, obtain permission for data use, measure outcomes, and document failures as carefully as successes.

## Phase 4 — Product

Create a release package containing technical documentation, terms of use, privacy notice, support process, dependency inventory, ownership records, and a deployment plan.

## Phase 5 — Scale

Expand only after product evidence, legal readiness, security controls, and operational capacity are strong enough to support the next level of exposure.

The roadmap is directional. Dates, budgets, staffing, and commercial milestones should be added only when they are supported by a real operating plan.
